# /sql修复

目标：由 Claude 基于 SQL、完整报错、目标方言和可获得事实先定位失败阶段，再给出保持业务语义的最小修复。修复不等于重写，更不等于把平台或资源故障伪装成 SQL 错误。

不要依赖错误关键词路由、固定补丁模板或旧流程状态。错误原文、SQL、元数据、计划和运行事实是证据；Claude 负责判断证据是否足以修复。

## 输入判断

直接理解以下信息：

- 待修复 SQL、完整模板变量、默认库和用户期望行为。
- 报错原文、错误码、cause chain、行列号、失败时间和客户端/引擎来源。
- SQL 方言、Hive 执行引擎与版本、相关 session 参数和 UDF 版本。
- Query ID、Application ID、MR Job ID；仅运行时或资源错误需要。
- SQL 中的表、CTE、别名、字段、函数、类型转换、分区、join、聚合、窗口和写入目标。
- 用户允许的修改范围，以及必须保持的字段顺序、粒度、过滤、去重、排序和写入语义。

保留原始报错文本和原 SQL 位置映射。不要在诊断前先格式化 SQL，以免行列号和用户日志无法对应。

## 触发澄清

遇到以下阻断情况时调用 `AskUserQuestion`：

- `sql_task_get` 无法取得任务或任务 SQL。
- 用户要求修复真实失败，但没有足以定位的报错原文、失败阶段或运行标识，且 SQL 本身没有确定错误。
- 报错字段、表、函数或 join key 有多个合理替代项，选择会改变业务含义。
- 修复需要在不同方言、引擎版本或 UDF 签名之间选择。
- 修复会改变 join type、过滤范围、聚合口径、重复行、NULL、排序或写入范围。
- 模板变量展开方式、默认库或动态分区值会决定修复结果但当前未知。

没有报错原文但 SQL 存在确定的静态错误时可以继续；只能得到候选原因时必须明确标记，不把“可能”包装成已修复。

## MCP 取数流程

读取 `references/mcp-interfaces.md`，只调用已实现工具，并根据失败阶段最窄取数：

0. 校验原任务 SQL 时调用 `hive_task_sql_validate(taskId)`，禁止复制或重构任务 SQL 后调用 `hive_sql_validate`。`hive_sql_validate` 仅用于验证候选修复 SQL。
1. 表/库解析错误：先核对默认库和限定名，再用 `hive_search_tables` 查候选；候选不唯一时澄清。
2. 字段、类型、别名或分区错误：用 `hive_get_columns`；需要确认分区结构时补 `hive_get_partitions`。
3. DDL、SerDe、存储格式、目标列或表属性问题：用 `hive_get_table_ddl`。
4. 字段来源不清：用 `hive_find_column_usage` 找候选来源，不自动替换。
5. join 放大、重复或唯一性相关问题：用 `data_map_get_table_primary_keys` 获取主键记录，但不把它当作运行数据唯一性证明。
6. 函数不存在或签名不确定：先用 `hive_function_search` 确认当前集群已注册函数，再用 `hive_function_get` 读取实际签名和说明。
7. 运行时、资源或平台失败先用 `mapreduce_job_search` 定位，再用 `mapreduce_job_diagnostics_get` 和必要的 `yarn_application_diagnostics_get` 获取事实；历史过期时依赖用户日志并说明限制。
8. 涉及近期落盘时可调用 `hive_table_freshness_get`；业务术语、业务 SLA 或历史端到端时间线接口未实现时，不假装做过对应验证。

不要为一个局部错误加载所有表元数据，不读取无关历史运行或完整容器日志。

## 修复流程

1. **还原失败上下文**：确认实际提交 SQL、变量、默认库、方言、版本、用户和失败时间。
2. **定位失败阶段**：按客户端/模板、词法/语法、编译/语义、元数据、计划、运行时数据、资源/基础设施、写入/commit 分类。
3. **定位最小范围**：优先使用错误码和行列号，再结合 cause chain；只有无定位信息时才逐个 SQL block 排查。
4. **验证直接依赖**：只核对出错片段涉及的别名作用域、表字段、类型、函数签名、分区和目标 DDL。
5. **区分根因与连带错误**：优先修复最底层、最早出现且有证据的原因；不要逐条改写后续派生报错。
6. **形成最小补丁**：保留原 SQL 结构、字段顺序、过滤、join、聚合、排序、注释和写入目标，只修改导致失败的必要部分。
7. **检查语义影响**：核对 NULL、重复、类型精度、时间边界、outer join、聚合粒度、窗口和覆盖范围。
8. **分层验证**：先做文本/作用域复查，再做元数据核对；解析器或只读计划接口已实现时按需调用。当前 Agent 不执行 SQL。
9. **处理非 SQL 根因**：如果证据指向队列、节点、OOM、fetch failure、锁、Metastore 或存储故障，明确给出对应处置方向；除非 SQL 也有可证明问题，否则不制造修复 SQL。

## 错误分类与动作

| 失败层 | 关键证据 | 允许动作 | 禁止动作 |
| --- | --- | --- | --- |
| 模板/客户端 | 未展开变量、截断 SQL、错误默认库 | 修正变量或提交上下文 | 猜变量值 |
| 词法/语法 | 引擎错误码、行列号、目标方言语法 | 修正 token、括号、关键字和子句位置 | 借机重写业务逻辑 |
| 编译/语义 | 字段解析、别名作用域、group/window/type 错误 | 基于作用域和元数据最小修正 | 用相似字段名替代真实字段 |
| 元数据/分区 | 表字段/分区/DDL 与 SQL 冲突 | 修正限定名、列映射或分区语法 | 自动建表、补分区或执行 DDL |
| 函数/UDF | 函数不存在、签名或版本不匹配 | 使用已确认签名或兼容函数 | 创造 UDF 或静默改变 NULL/精度 |
| 运行时数据 | cast/解析/溢出/除零等数据触发证据 | 给语义明确的保护或隔离方案 | 未见数据便断言脏数据分布 |
| 资源/平台 | JobHistory、YARN、container、queue、node、lock 证据 | 归类平台或资源处置，必要时给降低资源的候选方案 | 宣称改语法即可解决 |
| 写入/commit | 目标 schema、动态分区、文件系统错误 | 保持目标与覆盖范围的最小修复 | 扩大 overwrite、删除数据或自动 DDL |

## 修复约束

- 只修复有证据的问题；同义改写、格式化和“顺便优化”不属于修复。
- 不替换未确认的表、字段、函数、join key、分区或模板变量。
- 不自动建表、补分区、修改表结构或执行任何 DDL/DML。
- 类型修复必须说明目标类型、精度、溢出、非法值和 NULL 行为；不默认用宽松 cast 吞掉错误。
- group by、distinct、窗口、outer join、union 和 anti join 的改动必须保持原结果契约。
- 不把 `insert overwrite` 改成其它写入方式，不调整目标列和分区范围，除非用户确认。
- 无法证明完整 SQL 安全时只给局部补丁或不可直接执行的骨架，不包装成完整修复。
- 解析通过不等于运行成功；一次错误消失也不等于结果正确。

## 输出格式

根据问题自然组织中文 Markdown，不强制输出空章节。结果应覆盖：

- **错误定位**：失败阶段、位置、直接原因、根因及证据来源；区分确定与推断。
- **修复 SQL/补丁**：可靠时使用 `sql` fenced code block；非 SQL 根因或事实不足时不强行输出。
- **改动说明**：逐条说明原问题、最小修改和语义影响。
- **验证建议**：解析、元数据、结果契约和必要运行验证分别检查什么。
- **剩余限制**：缺少的日志、版本、运行或数据事实。

## 质量闸门

输出前确认：

- 使用的是实际提交 SQL 和原始报错，没有因预先格式化破坏行列定位。
- 已区分语法、语义、运行时、资源/平台和写入故障。
- 修复针对最早且证据充分的根因，没有逐个追逐连带错误。
- 没有把未确认字段、函数、分区、变量或错误原因写成事实。
- 没有静默改变过滤、join、聚合、NULL、重复行、排序或写入语义。
- 平台/资源问题没有被伪装成 SQL 修复。
- 未实现的业务术语、业务 SLA 和历史时间线接口没有被声称已调用。
- 没有声称 SQL 已通过解析、执行或结果验证。
