# /sql静态检查

目标：用可重复、可定位、确定性高的规则检查 SQL 文本风险。静态检查只回答“当前规则发现了什么”，不能证明业务语义正确、SQL 可执行、性能良好或可以上线。

当前命令由 Agent 本地确定性检查器直接处理，不经过 Claude 推理和 MCP。本文同时约束当前规则含义以及后续接入解析器和元数据检查时的边界；未实现的检查不能出现在结果中。

## 输入判断

检查输入包括：

- 原始 SQL 文本；当前结果保留原文，但不返回规则命中的行列位置。
- 用户或上下文明确给出的 SQL 方言与引擎版本。
- 用户指定的关注范围，例如安全、扫描、分区、可维护性或写入风险。
- 可选默认库和表上下文；当前本地检查器不使用这些外部事实。

SQL 为空时直接返回 `EMPTY_SQL`，不推断用户想生成什么 SQL。当前多语句会统一检查并汇总规则码，不返回 statement index。

## 触发澄清

静态检查通常不澄清：

- SQL 为空时直接报告 `EMPTY_SQL`。
- 方言未知或 SQLGlot 不支持时返回 `PARSE_ERROR`，提示确认 SQL 方言。
- 需要表、字段、真实计划或运行事实才能判断的问题，不通过追问强行完成，直接标为未覆盖能力。

只有用户要求“能否上线”“是否一定命中分区”等超出静态检查的问题，并且继续回答会形成错误结论时，才调用 `AskUserQuestion` 或明确能力边界。

## MCP 取数流程

确定性 AST 规则本身不把外部事实混入规则命中，因此：

- `FUNCTION_ON_PARTITION_FIELD` 只能表示 AST 中发现了 `DATE(字段)`，不能确认该字段真是分区字段。
- `NO_WHERE` 只能描述目标查询块缺少 WHERE 的结构事实，不能证明发生全表扫描。
- `SELECT_STAR` 只能描述投影形式，不能量化扫描或传输影响。

Agent 执行 `/sql静态检查` 时，在 AST 规则之后按命中范围补充真实事实：

1. SQLGlot AST 结果只作为结构事实，不能冒充 Hive 编译结果。
2. 只对规则涉及的表字段调用 `hive_get_columns`、`hive_get_partitions` 或 `hive_get_table_ddl`。
3. 函数或 UDF 不确定时调用 `hive_function_search/get` 核对当前 HiveServer2 的实际注册信息。
4. 需要目标引擎语法/语义结论时调用 `hive_task_sql_validate(taskId)`。
5. 仍然不获取 JobHistory/YARN 运行数据；需要真实瓶颈时属于 `/sql优化`，不是静态检查。

每项结论都必须标明实际来源；调用失败时保留缺口，不用模型记忆补事实。

## 检查流程

1. **保持原文**：只为匹配建立内部规范化视图，不修改返回给用户的 SQL。
2. **识别语句边界**：区分查询、写入、DDL 和多语句输入；注释与字符串字面量不能触发关键字规则。
3. **运行确定性规则**：每条问题包含唯一规则码、level、message 和 suggestion。
4. **汇总规则**：同一规则码在一次检查中只输出一次；当前按固定规则顺序返回。
5. **判定结果**：存在 `error` 才是“不通过”；只有 warning 或没有问题时是“通过，但不代表可上线”。
6. **声明覆盖范围**：列出实际执行的规则版本、方言和未执行的目标引擎编译、元数据、计划、运行验证。

## 当前已实现规则

只允许本地检查器返回以下规则码：

| 规则码 | 级别 | 确定内容 | 不能推出 |
| --- | --- | --- | --- |
| `EMPTY_SQL` | error | SQL 输入为空 | 用户业务目标 |
| `PARSE_ERROR` | error | 目标方言解析失败 | SQL 的业务意图或正确修复方式 |
| `SELECT_STAR` | warning | AST 投影中存在 `*` 或 `表.*` | 一定读取全部底层列或一定很慢 |
| `NO_WHERE` | warning | 至少一个带 FROM 的查询块没有 WHERE | 一定全表扫描或必须新增过滤 |
| `DANGEROUS_DDL` | error | AST 中存在 `drop table` 或 `truncate table` | 用户是否已获审批 |
| `FUNCTION_ON_PARTITION_FIELD` | warning | AST 中存在 `date(字段)` | 参数一定是分区字段或裁剪一定失效 |

当前实现使用 SQLGlot 解析目标方言 AST，但不是 Hive 编译器。规则结果必须保留上述限制，不能扩展成未执行的元数据或运行判断。

## 后续规则分层

只有在对应确定性能力实现并加入测试后，才可以扩展：

- **解析层**：语法错误、未解析对象、别名作用域、group/window 子句合法性。
- **安全层**：高风险 DDL/DML、多语句、无条件更新/删除、overwrite 范围。
- **元数据层**：不存在的表字段、真实分区函数、类型/列映射、目标表结构。
- **语义风险层**：outer join 过滤位置、NOT IN/NULL、union 去重、窗口排序不稳定；默认 warning，不自动修复。
- **治理层**：敏感字段、血缘和上线策略；必须由平台事实接口确认。

规则必须基于 parser/结构化 API 实现，不能持续堆叠脆弱字符串匹配。新规则上线前需要明确适用方言、误报边界、位置算法和测试样例。

## 输出格式

当前输出保持简洁：

- **检查结论**：通过或未通过，并说明“通过”只针对当前规则集。
- **SQL**：原样放入 `sql` fenced code block。
- **问题列表**：每条包含 level、规则码、问题和建议；位置可得时一并给出。
- **限制**：说明已执行 SQLGlot AST 解析，但未执行目标引擎编译、元数据、计划和运行验证。

没有问题时只能说“当前规则未发现明显问题”。通过不代表 SQL 可执行、性能良好或可以上线，不能说“SQL 正确”“可以上线”或“性能正常”。

## 质量闸门

输出前确认：

- 规则码来自当前实际实现，没有把人工推断包装成规则结果。
- 注释和字符串字面量不会触发危险 DDL 关键字误报；多语句仍只汇总规则码，不提供命中位置。
- warning 没有被说成不可执行，error 也没有被扩大成未验证的业务结论。
- `NO_WHERE`、`SELECT_STAR` 和函数信号没有被直接写成全表扫描或性能根因。
- “通过”只表示当前 error 规则未命中，不代表解析、结果或上线验收通过。
- 没有声称执行过 SQL、查询过元数据、获取过计划或完成过运行验证。
